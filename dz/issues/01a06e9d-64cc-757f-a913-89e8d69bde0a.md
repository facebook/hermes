Any use of the `-commonjs` flag past AST dumping aborts in a Debug build:

    $ echo '' > /tmp/e.js
    $ hermes -commonjs /tmp/e.js
    hermes: lib/IRGen/ESTreeIRGen.h:1518: FunctionContext *hermes::irgen::ESTreeIRGen::curFunction():
            Assertion `functionContext_ && "No active function context"' failed.
    exit 134

Reproduced on static_h at 3e37d5dc5 with a Debug build. It happens on an
empty file, so it does not depend on the input at all. `-dump-ir` fails the
same way. Only the AST dumps survive (`-dump-ast` and
`-dump-transformed-ast`), and `-dump-ast` does produce the expected
CommonJS wrapper.

The assertion is Debug-only, so the behavior of a Release build is unknown
and should be checked separately.

There appear to be no lit tests covering `-commonjs` end to end, which is
presumably why this went unnoticed. Adding one would be part of the fix.

The flag and its supporting machinery are still present and documented:
`-commonjs` and `-fstatic-require` in lib/CompilerDriver/CompilerDriver.cpp,
hermes/AST/CommonJS.h, sema::resolveCommonJSAST, and the VM-side Domain and
CJS module support in lib/VM/Runtime.cpp. So this reads as a regression
rather than a removed feature, but that has not been confirmed.

Found while verifying the claims in doc/Features.md.
