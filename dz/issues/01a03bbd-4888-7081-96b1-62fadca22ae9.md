Several tag-helper static_asserts in both backends use the form
static_assert(cond && "msg") - a valid one-argument assert whose
condition is cond && true, so the check still holds but the message is
silently ANDed into the condition instead of being the diagnostic.
Sweep both trees (arm64 and x86-64 JitEmitter-internal.h and friends) to
the two-argument form static_assert(cond, "msg").

One arm64 instance also carries a copy-pasted wrong message:
lib/VM/JIT/arm64/JitEmitter-internal.h's emit_sh_ljs_tag_is_string
asserts about HVTag_Str with the message "HV_TagObject must be -1". The
x86-64 copy already fixed the message text (with a comment noting the
deliberate divergence); fold that back when sweeping.

Message-quality only; no check is actually weakened. Found during the
x86-64 port's reviews.
