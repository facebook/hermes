# x86-64 JIT Skeleton (Milestone 1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An x86-64 JIT backend skeleton that builds with the JIT enabled
on x86-64 SysV, compiles and correctly executes trivial functions
(`enter`/`leave`, const loads, `LoadParam`, `Mov`, `Ret`), and declines
everything else to the interpreter — verified natively under ASan.

**Architecture:** New `lib/VM/JIT/x86-64/` tree implementing the same
`Emitter` surface the shared driver (`lib/VM/JIT/JitCompiler.cpp`)
compiles against, selected by a new branch in `JitCurArch.h`. The FR
register-file substrate is ported from arm64 (copy-and-rewrite per the
spec's sharing policy); every per-opcode emitter starts as an
`unsupported()` stub. Prerequisite: the arm64 sources gain arch
self-guards so both subtrees can be listed unconditionally in CMake.

**Tech Stack:** C++17, asmjit x86 backend (vendored, `asmjit/x86.h`),
CMake/Ninja, clang, native x86-64 ASan build + aarch64 qemu cross build.

**Spec:** `doc/superpowers/specs/2026-08-23-x86-64-jit-design.md`
(register convention, sharing policy, AVX gate, testing sections).

## Global Constraints

- Worktree `/home/tmikov/work/hermes-x86-jit`, branch `x86-jit`. NEVER
  `cd`; pass absolute paths (project rule).
- Builds:
  - arm64 reference: `cmake-build-arm64` (existing; qemu binfmt runs with
    `QEMU_LD_PREFIX=/usr/aarch64-linux-gnu`).
  - x86-64 host compilers: `cmake-build-host` (existing; JIT off).
  - x86-64 JIT dev build (created in Task 2):
    `cmake-build-x86jit`, ASan+Debug -O1, clang,
    `-DHERMESVM_ALLOW_JIT=2`.
- The arm64 backend must remain byte-identical: after any task that
  touches a file the arm64 build compiles, re-run the jit-diff gate
  against `cmake-build-arm64/jit-baseline.dump` (capture it first if the
  build tree lacks one, exactly as in the milestone-0 plan).
- Register convention (from the spec, binding): xRuntime=r15, xFrame=r14,
  rbp=frame pointer, callee-saved globals rbx/r12/r13 (rbx doubles as the
  return-value stash, mirroring arm64's x21), GPR temps
  rax,rcx,rdx,rsi,rdi,r8,r9,r10, r11=reserved scratch (never in
  `TempRegAlloc`), vector temps xmm0–xmm15, no vector globals. VEX
  encodings only for vector instructions (`vmovsd`, not `movsd`), AVX
  presence gated by CPUID at `JITContext` construction.
- rsp is 16-byte aligned at every emitted `call` instruction.
- C++: 80-column, 2-space indent, copyright header on every new file.
  Where a ported file diverges from its arm64 counterpart for a reason
  (not just encoding), mark the site with a `// x86-64:` comment.
- Commit messages end with:

- [ ] **Step 4: Create the Emitter header with the full surface**

Copy `lib/VM/JIT/arm64/JitEmitter.h` → `lib/VM/JIT/x86-64/JitEmitter.h`
and rewrite the arch-specific substrate declarations, keeping the METHOD
SURFACE (every public method the shared Compiler calls, plus the members
it touches: `emittingIP`, `code`, the ctor signature, `StringSwitchCase`)
character-compatible. Required substrate rewrites:
- `#include "asmjit/a64.h"` → `#include "asmjit/x86.h"`;
  `namespace a64 = asmjit::a64;` → `namespace x86 = asmjit::x86;`;
  assembler type `a64::Assembler` → `x86::Assembler`.
- Register constants (replacing the arm64 x19/x20/x21 block):

```cpp
// x86-64: SysV register convention (see the design spec).
static constexpr auto xRuntime = x86::r15;
static constexpr auto xFrame = x86::r14;
// Reserved scratch, never allocated by TempRegAlloc.
static constexpr auto xScratch = x86::r11;
// GPR temps: {rax,rcx,rdx} and {rsi,rdi,r8,r9,r10} (asmjit ids 0-2,6-10);
// rbx/rsp/rbp (3-5) sit between the ranges and are never temps.
static constexpr std::pair<uint8_t, uint8_t> kGPTemp1(0, 2);
static constexpr std::pair<uint8_t, uint8_t> kGPTemp2(6, 10);
// Callee-saved global pool: rbx (also the return-value stash, the x21
// analogue), r12, r13. Not contiguous, so a list, not a range.
static constexpr uint8_t kGPSavedList[] = {3, 12, 13};
// Vector temps: all of xmm0-xmm15; no callee-saved vector registers
// exist in SysV, so there are no vector globals.
static constexpr std::pair<uint8_t, uint8_t> kVecTemp(0, 15);
```

- `HWReg`: same class shape (combined index, Gp/Vec tag), with accessors
  `a64GpX()`/`a64VecD()` renamed to return `x86::Gp` (`x86::gpq(idx)`)
  and `x86::Xmm` (`x86::xmm(idx)`); pick names `gpq()`/`xmm()` and use
  them consistently in the .cpp files.
- `TempRegAlloc` members: `gpTemp_{kGPTemp1, kGPTemp2}` (the two-range
  form already exists for arm64's vector temps), `vecTemp_{kVecTemp}`.
- Everything the Compiler interacts with keeps its exact arm64 name and
  signature: the ctor (9 args), `enter(uint32_t, uint32_t)`,
  `leave(llvh::ArrayRef<const asmjit::Label *>)`, `newBasicBlock`,
  `newPrefLabel`, `addToRuntime`, `assertPostInstructionInvariants`,
  `emitPendingTypeAsserts`, `emittingIP`, `code`, `unsupported...`
  mechanism, `StringSwitchCase`, and all ~150 per-opcode methods. Do not
  drop any method even if its Task-2 body is a stub — link errors against
  `JitCompiler.cpp` are the completeness check.
- Delete arm64-only private helpers that Task 2/3 will not port yet ONLY
  if nothing kept references them; when in doubt keep the declaration.

   used entry of `kGPSavedList` (rbx is ALWAYS saved — it is the return
