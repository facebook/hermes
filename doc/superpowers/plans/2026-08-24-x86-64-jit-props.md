# x86-64 JIT Property Access, ICs and Literals (Milestone 4) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The x86-64 JIT compiles and correctly executes object and array
literals, property reads/writes through the three-tier inline caches,
globals, and the fast-array family — real object-oriented JS runs in
machine code — and the HV32/BOXED build matrix becomes load-bearing,
compiling the compressed-pointer branches for the first time.

**Architecture:** Port three arm64 files: `JitEmitter-object.cpp` whole
(literal buffers are `alloc2InYoung`'s first caller; needs
`initHCLazyIDMayAlloc` from arm64 `JitEmitter.cpp` — the HiddenClass
lazy-JIT-ID pinning through `usedHCs`), `JitEmitter-property.cpp` whole
(the `GetByIdImpl` IC engine: object-specialization, parent-
specialization, generic tiers; `putByIdImpl`; plus `getGlobalObject`/
`declareGlobalVar` from arm64 `JitEmitter.cpp`), and the array/fast-array
subset of `JitEmitter-array.cpp` (iterators/arguments/for-in stay in
milestone 5). Then stand up the HV32 and BOXED builds and make the
differential matrix pass.

**Tech Stack:** as before, plus two new build trees:
`cmake-build-x86jit-hv32` (`-DHERMESVM_HEAP_HV_MODE=HEAP_HV_PREFER32`)
and `cmake-build-x86jit-boxed` (`-DHERMESVM_HEAP_HV_MODE=HEAP_HV_BOXED`),
both ASan+Debug -O1 clang with `-DHERMESVM_ALLOW_JIT=2`.

**Spec:** `doc/superpowers/specs/2026-08-23-x86-64-jit-design.md`
(milestone 4; the Testing matrix). The free-after-call invariant and the
allocation-helper preconditions in `doc/JIT.md`/`JitEmitter.h` BIND all
emitters here.

## Global Constraints

Same as milestones 2-3 (worktree, no `cd`, arm64 files as reference with
`// x86-64:` divergence comments, VEX only, rsp%16==0 at calls,
differential lit pattern with compile-status pinning at BOTH -O and -O0
where a -O0 RUN exists, full x86 check-hermes + ASan + prove-can-fail
per task, 80-col, commit trailer). Additions:

- **GC pinning discipline:** HiddenClass references from emitted code are
  lazy JIT IDs, never raw pointers; every HC used gets pinned via
  `initHCLazyIDMayAlloc`/`usedHCs` exactly as arm64 does. Any deviation
  is a Critical review finding.
- **The allocation-helper preconditions** (no live vector temp, nothing
  in r11, out/temp not r11 across `allocInYoung`/`alloc2InYoung`) now
  have many new call sites — cite the precondition comment at each new
  call site that is not a direct arm64 transcription.
- **Carry-over obligations embedded in this plan:** `alloc2InYoung`'s
  first caller (Task 1); `createTopLevelEnvironment` coverage +
  `getGlobalObject`/`declareGlobalVar` (Task 2); `emit_double_is_uint32`
  port when the array paths need it (Task 3); the cp-helper HV32
  branches' first compile (Task 4).
