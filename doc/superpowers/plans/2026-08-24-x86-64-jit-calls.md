# x86-64 JIT Calls, Environments and Closures (Milestone 3) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The x86-64 JIT compiles and correctly executes function calls
(direct, N-ary, builtin, construct), environments and closures —
recursive and higher-order JS runs in machine code — including the
young-gen inline allocation path that environment creation requires,
verified natively under ASan.

**Architecture:** Port three arm64 files essentially whole:
`JitEmitter-alloc.cpp` (bump allocation + cell init; pulled forward from
the spec's milestone 4 because environments allocate inline),
`JitEmitter-env.cpp` (environments, closures, classes, generators), and
`JitEmitter-call.cpp` (the SH ABI frame dance, `callImpl`'s
JIT-to-JIT fast path, builtins, construct), plus the internal helpers
they use (GC-cell kind checks, compressed-pointer load/store in both
heap modes, environment init) and `emitIncrementCounter`.

**Tech Stack:** as milestone 2 (`cmake-build-x86jit` ASan native,
`cmake-build-arm64` qemu reference).

**Spec:** `doc/superpowers/specs/2026-08-23-x86-64-jit-design.md`.
The free-after-call invariant paragraph in `doc/JIT.md` (added by the
milestone-2 review) BINDS every emitter in this plan.

## Global Constraints

Same as milestone 2 (worktree, no `cd`, x86-64-tree-only changes, arm64
files as reference with `// x86-64:` divergence comments, VEX only,
rsp%16==0 at every emitted call, differential lit-test pattern with
compile-status pinning, full x86 check-hermes + ASan + prove-can-fail
per task, 80-col, commit trailer). Additions:

- **Free-after-call:** every emitted call site must
  `syncAllFRTempExcept`/`freeAllFRTempExcept` exactly as its arm64
  counterpart; the type-assert build turns violations into spurious
  traps, so run each new test with `-Xjit-emit-type-asserts` as a third
  RUN line from the start.
- **ASan is load-bearing this milestone:** the young-gen bump-allocation
  path must replicate arm64's shadow-memory handling
  (`bumpAllocAndUnpoison`) exactly; our dev build exercises it on every
  allocation. Port any sanitizer conditionals faithfully.
- **Register conventions for the call fast path** (translating arm64's
  x0/x1/x2 usage in `callImpl`): rdi = Runtime (first SysV arg),
  rsi = Callable* (second arg to the jitCall/compiled function), the
  loaded call target goes in a third register — use rax or rdx (NOT r11
  if the slow path needs the value across its own materializations;
  choose and document). All temps are free at that point (arm64 relies
  on the same fact).
- Compressed-pointer helpers (`emit_load_cp`/`emit_store_cp` etc.) are
  ported with BOTH `#ifdef HERMESVM_COMPRESSED_POINTERS` branches for
  arm64 parity, even though the dev build only exercises HV64; the HV32
  build matrix arrives with the next milestone per the spec.

### Task 2: Calls

**Files:**
- Create: `lib/VM/JIT/x86-64/JitEmitter-call.cpp`
- Modify: `JitEmitter.h`, `JitEmitter-internal.h` (gccell/cellkind
  helpers), `JitEmitter.cpp` (`emitIncrementCounter`, standalone
  `getBytecodeIP` if not already factored), `JitEmitter-stubs.cpp`,
  `lib/VM/CMakeLists.txt`
- Create: `test/jit/x86-64/calls.js`
- Modify: `test/jit/x86-64/closures.js` (enable `nest`'s CHECK)

**Port sources (arm64):** `JitEmitter-call.cpp` whole (19-567:
createThis, selectObject, loadThisNS, coerceThisNS, getNewTarget,
callImpl, call, callN, callBuiltin, callWithNewTarget,
callWithNewTargetLong, callRequire, getBuiltinClosure) — note
`selectObject` carries an `emitTypeAssert` site (the 23rd; arm64
JitEmitter-call.cpp:513-ish) and its guard-ordering subtlety is
documented in the type-assert design docs; port verbatim.
`emitIncrementCounter` from arm64 `JitEmitter.cpp:606-` (loads the
counter array pointer from `RuntimeOffsets::runtimeJitCounters`, then a
64-bit increment — on x86 a single
`inc qword ptr [reg + idx*8]` after the pointer load).
Helpers: `emit_gccell_get_kind`, `emit_cellkind_in_range` (the
sub+unsigned-compare range trick — translate to 32-bit `lea`/`sub` +
`cmp`+`ja`), `emit_load_builtin_closure`.

`callImpl` mapping (the milestone's core): outgoing frame slots are set
through the FR machinery exactly as arm64 (the outgoing area is part of
`frameRegs_`); object check → `emit_sh_ljs_get_pointer` → cell kind →
CodeBlockFunctionKind range check → `codeBlockJitPtr` null check →
direct `call`; slow path indexes `VTable::jitCallArray` by kind. The
called function (both paths) receives rdi = Runtime, rsi = Callable*;
keep the kind in the register the slow path expects (arm64 keeps kind in
x0, callee in x1, target in x2 — map to eax/rsi/+target and keep the
fast/slow register contract IDENTICAL between the two paths, as arm64
does; document the chosen mapping in one comment above `callImpl`).
`getBytecodeIP` on x86 is an absolute `mov reg, imm64` (the bytecode
address is a process constant — milestone 1 established this in
`callRuntimeWithSavedIP`; factor to share if not already).
The non-object-call shared slow path (`nonObjCallLabel_`) ports as-is.

addEmptyString), typeof/instanceof/in, switches, exceptions/try,
iterators/generators-resume (CreateGenerator only creates the object),
for-in, `arguments`, HV32/BOXED matrix, goldens. `jmpUndefined` remains
unreachable (for-in). Slow-path-only fallbacks stay wherever arm64 has
them.
